# 菜单栏用量摘要

## 悬浮状态灯的平台切换

点击悬浮灯的会话数量角标后，直接点击需要显示的 Codex 或 Claude 状态卡片。选择会立即更新悬浮灯和菜单栏灯的来源，保留其他平台的会话列表和监控，便于随时切回；不会切换登录账号。选中卡片带勾选和边框，手动来源会保存，重复点击不会取消选择。面板仅显示状态卡片，不再显示顶部的“自动／Codex／Claude”按钮。所选平台未运行时显示空闲，不回退显示另一个平台的灯效；暂停和调试覆盖仍优先。

2026-10-30 卡片界面简化：按用户要求移除顶部三个按钮及其布局辅助函数，保留卡片按钮和选中标记。5 项相关隔离测试通过；更新并重启后，在实际悬浮信息窗口确认只显示状态卡片。

当前悬浮配额与 Token 角标的数据源为 Codex。选择 Claude 时隐藏这两个 Codex 专属角标，防止误当作 Claude 用量；Claude 的订阅配额和本地 Token 可在用量页和菜单的 Claude 摘要中查看。

2026-10-30 平台切换验证：15 项隔离测试通过，包括两种灯的来源隔离、手动选择持久化、重复选择、恢复自动跟随、所选平台未运行时保持空闲、Claude IDE 来源识别，以及悬浮灯拖动回归检查。在 WindowServer 环境中用虚构会话渲染并切换同一窗口，核对灯区实际像素从 Codex 工作的绿色变为 Claude 待授权的红色，验证无需等待新状态事件。未操作当前运行实例或真实账号。

2026-10-30 授权重启后的实际点击验证：用户明确允许替换并重启后，通过项目 Run 脚本启动新版，并开启原先关闭的悬浮显示。补齐数量角标的辅助功能按钮动作、根视图的子控件可访问性，以及无标题信息面板的输入焦点；修复后上述 15 项隔离测试再次通过。在真实应用中点击 Claude 来源按钮，确认选中标记同步、无活跃 Claude 会话时灯效为空闲且隐藏 Codex 用量角标；随后点击 Codex 状态卡，确认切回实时工作灯效并恢复 Codex 角标。关闭并重新打开面板后选择仍保留，点击“自动”可恢复跟随。结束时保留悬浮显示开启和自动跟随。当前没有活跃 Claude 状态卡，因此本轮不声称已复测其活跃会话的完整事件链；未修改登录账号或 Hook 配置。

## 菜单摘要与账号

系统菜单与卡片面板均不使用内嵌滚动容器，按内容自然确定高度；共用 `MenuUsageSummaryView`：平台切换、当前账号与套餐、配额剩余比例与重置时间、今日／近 30 天双列 Token 与估算费用、固定显示 Token 的近 30 天柱状图。柱状图读取现有扫描结果，随平台切换；悬停显示当天 Token 和估算费用，详情行固定高度，避免菜单跳动。两处都显示扫描进度，并保留旧结果。缺失用量显示破折号；失败与上次读取结果明确标注。Codex 的来源、账号上下文与限制 ID 继续保留，本地观察单独标识，不跨来源合并。

系统菜单通过系统“切换账号”子菜单操作，卡片面板使用账号按钮。Claude 保存账号来自可选 cswap。点击“用量与账号设置”或“管理账号”会跳到对应平台的用量页。菜单与设置共用 ClaudeSupportModel，不创建独立账号快照。菜单关闭会释放系统菜单宿主，停止其定时刷新。

卡片面板保留监控控制，运行记录通过设置窗口查看。更详细的历史模型拆分、专项配额及认证配置留在设置页。

此前验证使用隔离模型、虚构账号与扫描 fixture；已检查系统菜单的平台切换、系统账号子菜单、Codex/Claude 设置跳转，以及卡片面板的配额和扫描进度。这些验证未执行真实账号切换。本次柱状图增补已通过 macOS 构建检查，并重新编译启动本地 App；未发布版本。

本次无滚动布局通过 16 项相关测试，并以虚构账号和 30 天数据渲染验收：验证两种菜单的宽高、完整内容尺寸以及没有 NSScrollView。系统菜单的宿主在内容变化时同步高度，悬停详情保持固定高度。

系统菜单的高度更新会合并到主 RunLoop 的下一轮，在普通与菜单 tracking 模式均能执行；不在 SwiftUI 宿主的当前布局过程内改变菜单项高度，避免 macOS 27 的玻璃背景重复应用高度变化而与窗口错位。新增真实 NSMenu tracking 回归测试，覆盖内容增长、部分收缩与恢复初始高度，并核对背景和窗口始终对齐；fixture 不使用真实账号或用量。

## 设置中的 Codex 项目与会话明细

设置 → 用量 → Codex 的 Token 图表下方显示近 30 个自然日的项目与会话。项目按完整日志路径区分（同名目录不合并），按 Token 降序排列；点击项目筛选会话，可搜索路径、会话 ID 与模型，并分批展开列表。项目与会话默认收起，只显示数量；整行标题（箭头、文字、数量及空白区域）均可点击展开或收起，支持按钮键盘操作；展开后分别显示 3 个项目和 5 个会话，每次“显示更多”追加相同数量，收起后恢复首批数量。会话显示模型、输入、缓存、输出、总 Token、最近用量事件时间和估算费用。缓存 Token 已包含在输入中；未知费用显示破折号，部分定价合计显示 ≥。

明细复用已确认的 Codex 扫描缓存及定价逻辑，排除重复副本、冲突来源、Pi 导入和未完成扫描的实时用量，不归属于所选账号。项目仅从有大小上限的 session_meta 头读取 cwd；头不可读或身份不匹配归入“未识别项目”。成功扫描后替换明细，失败保留上次结果；明细不参与实时计数吸收，因此实时总量仍在核对时也能显示已确认的历史及扫描时间。此功能当前对应 Codex 本地日志。

设置中的 Token 图表在下方保留适量留白与提示；悬停详情在该区域内展开，高度只根据当前日期的内容自然增减，不预留所有日期的最大高度，也不显示浮层或系统工具提示。移过柱形间隙时保留当前详情，离开整个柱形区域后恢复留白，避免间隙触发反复收起。

## Codex credits（2026-11-12）

菜单、用量设置和悬浮额度详情现在展示当前账号的 credits 余额；月度 credits 与独立余额可分别显示。它们与“限额重置次数”、本机 Token 的估算费用分开。

当任一尚未重置的额度窗口耗尽且有有效正数余额时，悬浮角标自动切换为 `125c` 之类的 credits 数值，额度恢复后返回原百分比窗口。仅有 credits 的返回同样支持；未知、过期或刷新失败的余额不当作零或实时可用额度。完整规则与隔离验证见 [credits 核验记录](audits/2026-11-12-codex-credits/README.md)。
