# Agent Signal Bar v1.5.9

macOS 14+ · Apple Silicon + Intel · Build 19

## English

### Highlights

- Restores Codex Token history and cost reporting when large session histories or duplicate records interrupt scanning.
- Simplifies Codex quota presentation, removing redundant local-observation cards and misleading scope warnings for verified account responses.
- Restores dragging to reposition the desktop floating signal while keeping badge clicks and resizing separate.

### Improvements

- Retains confirmed history and live Token counts while local session files are changing. An unavailable or failed scan is no longer presented as measured zero usage.
- Reuses validated scan progress during retries within the same app run, reducing repeated work when new session files appear during a long scan.
- Keeps local-device Token totals separate from account-specific quota, with clearer account attribution and data-source labels.
- Prevents late quota responses from a previous account or credential set from updating the currently selected account.
- Strengthens per-user signal-state storage and makes Hook installation and removal safer with backups, concurrent-change checks, and guarded rollback.
- Improves Codex CLI discovery in login-shell environments and runs provider checks in the background to keep the interface responsive.

### Fixes

- Uses each Codex session's own ID instead of mistaking a shared parent ID for the session identity, preventing unrelated child sessions from being grouped as duplicates.
- Resolves false record conflicts when an interrupted, noncontributing log shares an ID with a token-bearing log. Original logs are preserved; changed copies are checked again, and genuine conflicting usage remains excluded with a warning.
- Recalculates inherited child-session usage when a parent's conflict is resolved or its previously empty history becomes available, avoiding stale or duplicated totals.
- Suppresses the missing-scope label only for a fresh, successfully verified OAuth quota response belonging to the selected saved account. Uncertain attribution is not silently treated as verified.
- Shows local quota observations only as a fallback when the primary quota is unavailable, rather than displaying an additional competing card. Unavailable quota windows are not silently replaced with a different period.
- Corrects floating-signal hit testing and native window dragging, including repeated drags and input priority for badges and resize handles.

### Upgrade notes

- The first refresh may recheck session identities and refresh usage caches. Historical totals can change as previously excluded records are recovered and duplicate counting is corrected; Codex's original session logs are not rewritten or deleted.
- Token usage is a local-device session summary, not usage attributed to the currently selected account. Charts and estimated costs reflect scanned history; newly observed live Tokens may appear before their cost is available.
- A record-conflict warning can still appear when multiple logs contain genuinely inconsistent usage or cannot be safely verified. Other trusted history and live counts remain available.
- Signal status now defaults to a private per-user Application Support directory; legacy shared temporary state is not automatically imported. If a custom integration hardcodes the old state location, use the updated bundled CLI or explicitly configure the same secure state location for both the app and the integration. This change concerns signal status, not Codex conversation history.

### Release verification

- Latest local verification on September 3, 2026: 441 Swift tests passed with 0 failures, including 23 new regression tests for noncontributing duplicates and live/history reconciliation.
- All 10 Hook installation, concurrent-write protection, and rollback regression tests passed.
- The local debug build compiled and launched. The reported duplicate-log conflict was also verified as resolved against the affected local records, without modifying those records.
- Before publishing the downloadable assets, the release workflow requires universal Release packaging, Apple Silicon and Intel architecture checks, ZIP/DMG installation and uninstall checks, CLI/Hook integration checks, code-signature and checksum verification, and both Sparkle update feeds.
- This is an ad-hoc-signed macOS build without Developer ID signing or Apple notarization.

## 简体中文

### 亮点

- 修复大型会话历史或重复记录导致扫描受阻时，Codex Token 历史与费用无法正常显示的问题。
- 精简 Codex 配额展示，移除重复的本地观察卡片，以及已验证账户响应中具有误导性的额度范围提示。
- 恢复桌面悬浮灯的拖动移动，同时保留角标点击和缩放操作各自的响应区域。

### 改进

- 本机会话文件持续变化时，保留已确认历史和实时 Token；扫描尚未完成或失败，不再被显示为已测得的零用量。
- 在同一次 App 运行中的扫描重试之间复用已验证进度，减少长时间扫描遇到新会话文件时的重复工作。
- 明确区分本机 Token 汇总与账户配额，补充更清晰的账户归属和数据来源说明。
- 账户或凭据切换后，阻止旧请求迟到的配额结果更新当前所选账户。
- 加强用户私有信号状态存储，并通过备份、并发修改检查和受保护的回滚，提高 Hook 安装与移除的安全性。
- 改善登录 Shell 环境中的 Codex CLI 发现能力，并在后台执行服务状态检查，减少对界面响应的影响。

### 修复

- 优先使用 Codex 会话自身 ID，避免将共享的父会话 ID 误当成当前会话身份，从而把不同子会话错误归为重复记录。
- 修复无用量的中断日志与正常用量日志共用 ID 时产生的误报冲突。保留原始日志，副本发生变化后重新核验；真正有分歧的用量仍会被排除并显示警告。
- 父会话冲突解除，或原本为空的父会话历史恢复后，重新计算子会话的继承用量，避免沿用旧结果或重复计数。
- 仅对当前所选已保存账户、刚刚成功验证的 OAuth 配额响应，省略缺失范围名称时的提示；不会把归属不明确的数据当作已验证数据。
- 有主要配额数据时不再额外显示本地观察卡片；主要配额不可用时才使用本地观察作为备用。所选额度周期不可用时，不再悄悄替换成其他周期。
- 修正悬浮灯的鼠标命中区域与原生窗口拖动，覆盖连续拖动、角标点击及缩放控件的响应优先级。

### 升级说明

- 更新后的首次刷新可能重新核验会话身份并更新用量缓存。恢复此前排除的记录、纠正重复计数后，历史总量可能调整；不会改写或删除 Codex 原始会话日志。
- Token 使用是本机会话汇总，不代表当前所选账户的独立消耗。图表与预估费用以已扫描历史为准，新产生的实时 Token 可能先于费用显示。
- 如果多份日志确实包含不一致的用量，或无法安全核验，仍会显示记录冲突提示；其他可信历史和实时计数会继续保留。
- 信号状态默认改用每个用户私有的 Application Support 目录，不会自动导入旧共享临时目录中的状态。如果自定义接入脚本写死了旧状态路径，请使用更新后的随包 CLI，或为 App 与接入脚本显式配置同一个安全的状态位置。这项调整影响的是信号灯状态，不是 Codex 对话历史。
